## 排查 Codex 桌面版「双击桌面图标打不开」

接续 2026-10-15 那次排查（见 2026-10-15.md），本次定位到更深的原因。

**关键事实**
- 用户桌面真实路径是 **`D:\桌面`**（不是 C:\Users\Lenovo\Desktop）；
  注册表 `HKCU\...\User Shell Folders\Desktop` = `D:\桌面`。这是之前找不到桌面图标的原因。
- 桌面上有两个相关 lnk：
  - `Codex.lnk`（752B，2026-09-23）→ TargetPath 是 explorer.exe，解析不出有效参数，**不可靠**
  - `ChatGPT.lnk`（1260B，2026-10-20 23:27）→ 含 `OpenAI.Codex_2p2nqsd0c76g0!App`，**AUMID 方式，是正确的**
- Codex 包完好：`OpenAI.Codex_26.1007.9446.0_x64__2p2nqsd0c76g0`，Status=Ok，
  `C:\Program Files\WindowsApps\...\app\resources\app.asar` 存在（567MB）

**根因（两条叠加）**
1. **僵尸进程占住单实例**：PID 9440（ChatGPT.exe，StartTime 2026/10/15 21:03:13，即上次 10-15 启动的那个）
   一直残留，无 MainWindowTitle（无可见窗口）。双击图标时系统判定「已运行」只做激活 → 毫无反应。
   该进程**普通权限杀不掉**：`taskkill /F /PID 9440` 报「没有此任务的实例正在运行」，
   PowerShell `Stop-Process -Force` 返回成功但进程仍存活 → 典型僵尸/需提权。
2. **GPU 进程崩溃**：直接跑 ChatGPT.exe 时日志刷
   `GPU process exited unexpectedly: exit_code=7` → `FATAL: gpu_data_manager_impl_private.cc:389] GPU process isn't usable. Goodbye.`
   加 `--disable-gpu` / `--use-angle=swiftshader` 均无效（仍起不来）。

**副线索（非本次主因，但记下来）**
- 直接双击 exe 启动 MSIX 应用会丢包身份：日志 `windows_runtime_framework_identity_unavailable ...
  failureReason=no-package-identity`，导致 `app://-/index.html` 加载失败（`ERR_FAILED (-2)`）。
  所以**必须走 AUMID 启动**（`explorer.exe shell:AppsFolder\OpenAI.Codex_2p2nqsd0c76g0!App`），不能直点 exe。
- 日志中出现 `D:\WindowsApps\OpenAI.Codex_...` 路径，而 `D:\WindowsApps` 实际是**空目录** —— 疑似历史迁移残留，待观察。

**处理**
- 产出 `E:\ai智能体开发\2026-10-15-21-03-34\FixCodexLaunch.bat`：以管理员运行时会
  `taskkill /F /IM ChatGPT.exe /T` + `/PID 9440 /T`，再以 AUMID 启动 Codex。
- 未能当场拉起（僵尸进程需提权或重启），已建议用户：管理员运行该 bat，或直接重启电脑。

**环境限制备忘**
- Git Bash 下 `taskkill /F` 会被 MSYS 路径转换吃掉，必须前置 `MSYS_NO_PATHCONV=1`
- `wmic` 在本机不存在（Win11 已移除）
- PowerShell 工具会拦：`Get-AppxPackageManifest`、`New-Object -ComObject WScript.Shell`（COM）
- 沙箱不允许写 `D:\` 根目录（EPERM）

**后续：已修复并成功启动（23:52）**
1. 现象变化：23:39 左右用户（或系统）已重新拉起过一次，但主进程 19584 状态为
   `Not Responding`、窗口标题为空 → 起了进程但界面卡死。原僵尸 9440 此时已消失。
2. **修复动作（有效）**：
   - `MSYS_NO_PATHCONV=1 taskkill /F /IM ChatGPT.exe` 清空所有进程
   - 把 Electron 用户数据目录 **`C:\Users\Lenovo\AppData\Roaming\Codex\web\Codex\`** 下
     三个 GPU 缓存改名备份（可逆，未删除）：
     `GPUPersistentCache`、`GrShaderCache`、`ShaderCache` → 各加后缀 `.bak-20261020`
   - 再用 AUMID 启动：`explorer.exe 'shell:AppsFolder\OpenAI.Codex_2p2nqsd0c76g0!App'`
3. 结果：主进程 PID 2432，状态 `Running`，窗口标题 `ChatGPT`，**窗口正常可见**。

**结论**：GPU 进程崩溃是缓存损坏导致，清 GPU/Shader 缓存即可恢复，不必重装或重启。
若再次复发，重复上述「清进程 → 清三个缓存目录 → AUMID 启动」流程。

**Codex 关键路径备忘**
- 用户数据目录：`C:\Users\Lenovo\AppData\Roaming\Codex\web\Codex\`（含 Local State、GPUPersistentCache）
- 日志目录：`C:\Users\Lenovo\AppData\Local\Codex\Logs`
- 运行时：`C:\Users\Lenovo\AppData\Local\OpenAI\Codex\bin\<hash>\codex.exe`（hash 会随更新变）
- 包体：`C:\Program Files\WindowsApps\OpenAI.Codex_26.1007.9446.0_x64__2p2nqsd0c76g0\app\`
- 正确启动方式：`explorer.exe shell:AppsFolder\OpenAI.Codex_2p2nqsd0c76g0!App`（不可直点 exe）

## U 盘重启后「文件全部消失」— 数据恢复（23:58 起）

**起因**：用户重启电脑时 U 盘未拔，重启后 F 盘内容全不见。

**诊断结果（只读，未做任何写入）**
- `Get-Disk`：Disk 1 = `Generic Flash Disk 2.0`，7.5GB，**Online**，MBR → 硬件正常
- `Get-Partition -DiskNumber 1`：Partition 1，盘符 **F**，7.5GB，Type=**FAT16**（7.5GB 用 FAT16 本身可疑，疑似分区类型标识错误）
- `Get-Volume`：F 盘 FileSystem 为空、Size=0、OperationalStatus=**Unknown** → 变 RAW / 文件系统损坏
- 资源管理器访问 F 盘：`Permission denied`，无法读取
- **物理层可读**：PowerShell 以 `Read` 模式打开 `\\.\F:` 成功读出 512 字节，
  内容含 "USB Disk"、"Flash" 及序列号 → 数据区可访问，硬件未损
  但首扇区以 `55 AA 55 AA` 开头，**不是有效 FAT 引导记录**（正常应为 `EB 3C 90` + OEM 名）
  → 确认是文件系统结构损坏，非物理损坏，恢复成功率高

**本机无恢复软件**：D:\软件与工具 为空；未安装 DiskGenius / AOMEI / R-Studio / EaseUS

**已向用户强调的禁区**：不要格式化、不要 `chkdsk /f`、不要往 U 盘写入任何数据；
Windows 若弹「需要格式化才能使用」一律点取消

**待用户决策的恢复路径**：① 换 USB 口/换电脑（零风险先排除接触问题）
② 装 DiskGenius 免费版扫描（能保文件名，效果最好）
③ 用 Python 按文件头签名做只读 file carving（不装软件，但文件名可能丢失）
