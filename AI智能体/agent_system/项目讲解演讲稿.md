## 【第一部分：项目背景】（1分钟）

老师，我做这个项目的起因是——现在大模型，比如豆包、通义千问，大家都会用，但它们有个问题：**只会"说"，不会"做"**。

比如说我让它"帮我写一份毕业论文"，它确实能输出文字，但它不会真的生成一个带封面、带页眉、带声明页的 Word 文件；我说"帮我跑一下这段代码"，它也不能真的执行然后告诉我结果。

所以我就想做一个东西，让大模型**真的能动手干活**。这就是现在业界说的 **AI Agent，也就是智能体**。

我的项目就是这个方向——基于阿里云的百炼大模型，做了一个能自己规划、自己调用工具、自己验证结果的智能体。

## 【第二部分：整体架构】（1.5分钟）

老师，我这个项目的代码我做了分层，一共五层。您看这个图：

**最上面是入口层**——就是 main.py，用户在命令行跟它对话的地方。我还额外做了一个网页版，用 Gradio 做的，浏览器就能打开。

**第二层是能力层**——就是它有哪几种工作模式。我做了五种：
- 第一种叫**快速对话**，就是普通的你问我答
- 第二种叫**自主任务**，这是核心——你说一句话，它自己规划、自己调工具干活
- 第三种叫**工具调用**模式
- 第四种叫**五阶工作流**
- 第五种叫**场景 Agent**，就是分了编程、论文、办公、视频四个专属分身

**第三层是工具层**——这是智能体能"动手"的关键。我给它做了 12 个工具，比如能执行 Python 代码、能读写文件、能用 pip 装包、能生成 Word、Excel、PPT、PDF，还有能读参考论文的 PDF。

**第四层是核心层**——就是大模型调用的封装，加上一个任务执行引擎。

**最下面是基础层**——就是记忆系统和配置管理。

我为什么要分层？因为**分层之后改起来方便**。比如以后我想换大模型，只改核心层那一个文件就行；想加新工具，只改工具层，其他地方不用动。这是软件工程里说的模块化。

## 【第三部分：核心功能——我重点讲这几个】（5分钟）

### 3.1 第一个核心：ReAct 自主推理

老师，这是我这个项目最核心的技术。叫 **ReAct**，就是 **Reasoning 推理 + Acting 行动** 的意思。

它的工作方式不是一次性把活干完，而是像人做作业一样：

**第一步**——它先想："这个任务我该怎么拆？"比如我说"帮我写个 Python 脚本"，它会先出一个计划：第一步分析需求、第二步写代码、第三步运行测试、第四步交付。

**第二步**——它进入一个循环：每一轮它都问自己"我现在该干什么？要不要调工具？"
- 如果需要写文件，它就输出一个 JSON，说"我要调用 file_write 工具，参数是 xxx"
- 然后我的程序真的去调这个工具，把文件写了
- 工具执行完，把结果返回给它
- 它拿到结果再想下一步："哦，文件写好了，接下来该跑一下试试"
- 然后它又输出"我要调用 code_executor 工具"
- 就这么循环，最多循环 20 轮，直到它说"做完了"

这个就是 ReAct 模式——**推理和行动交替进行**，不是一次性输出，而是一步一步来。

这里我做了一个容错处理。因为大模型输出 JSON 有时候格式不稳定，比如它可能在 JSON 外面包一层 markdown，或者多写几句废话。所以我做了三层解析：
- 第一层，直接解析 JSON
- 第二层，如果不行，就从 markdown 代码块里把 JSON 抠出来
- 第三层，实在不行，就找第一个 `{` 到最后一个 `}` 暴力截取

这个是实际做项目踩坑踩出来的——不能完全信任大模型的输出格式。

### 3.2 第二个核心：工具系统

老师，智能体之所以能"动手"，就是因为有工具。

我做了一个工具管理器，注册了 12 个工具。每个工具都有统一的格式——执行完返回一个字典，里面有 success 成功没成功、result 结果、error 错误信息。这样上层不用管每个工具具体怎么实现的。

我重点说几个工具：

**第一个是代码执行工具**：它把大模型生成的代码写到一个临时文件里，然后用项目的 Python 解释器真的去执行，把运行结果抓回来。有 30 秒超时保护，防止死循环。

**第二个是文档生成工具**：我用 python-docx 库做了 Word 生成器，用 openpyxl 做了 Excel 生成器，用 python-pptx 做了 PPT 生成器。大模型输出 markdown 格式的内容，我的工具会自动把 `#` 转成 Word 标题、把表格转成 Word 表格。

**第三个是论文生成工具**，这个是我专门针对咱们贵财做的——它能自动生成带封面、带页眉"贵州财经大学本科生毕业论文"、带声明页的标准 Word，字体字号都按学校要求来，宋体小四、1.5 倍行距。

还有个安全设计——系统命令工具我加了黑名单，像 `format` 格式化硬盘、`shutdown` 关机这种危险命令，它想调我也不让调。这个是安全意识。

### 3.3 第三个核心：记忆系统

老师，大模型本身是"无状态"的——每次对话它都不记得你上次说过什么。所以我自己做了记忆系统。

分两部分：

**短期记忆**：就是当前对话的历史。每说一句话就存成一个 JSON 文件，程序崩了也不丢。

**长期记忆**：这个是跨对话的。我做了四类——用户偏好、常见问题 FAQ、历史经验、知识库。比如说用户说"我喜欢中文注释"，对话结束后，我会再调一次大模型，让它从这轮对话里提炼出值得记住的信息，存到长期记忆里。下次对话的时候，我会把相关的记忆自动注入到上下文里，让它"想起"用户的偏好。

这里我用的是最简单的关键词匹配来检索记忆——把用户问题分词，和记忆里的文本做词面匹配，按命中数排序。这个比较轻量，不需要额外依赖。当然我知道这个有局限——中文分词效果不好，下一步可以升级成向量检索，用 FAISS 或者 Chroma。

### 3.4 第四个核心：场景化 Agent

老师，我还做了四个场景专属的"分身"：编程、论文、办公、视频。

因为同一个 AI 处理不同任务，提示词应该不一样。写代码的时候它该像个工程师，写论文的时候该像个学者。

每个场景 Agent 都是五步流水线——以编程场景为例：
- 第一步，环境检测，看看 Python 版本、装了哪些包
- 第二步，需求分析
- 第三步，代码生成
- 第四步，代码自检——检查安全性、可运行性、规范性
- 第五步，交付

这里我用了**工厂模式**——维护一个字典，场景名对应类名，主程序说"我要编程场景"，工厂就 new 一个对应的 Agent。以后加新场景只要在字典里加一行，主程序不用改。

## 【第四部分：工程上的几个细节】（2分钟）

老师，做这个项目的时候，我在工程上注意了几个点：

**第一个，产出物验证**。大模型经常"吹牛"，说"我已经生成文件了"，但其实根本没写。所以我跑完任务后，会用 file_info 工具去检查文件是不是真存在、大小是不是大于 0。说了不算，查了才算。

**第二个，上下文窗口保护**。对话越长，token 越多，API 有长度限制而且贵。所以 ReAct 循环里我只带最近 10 轮对话，早期的历史交给记忆系统管。

**第三个，依赖注入**。所有模块都共享同一个 memory 实例，这样任何模块产生的经验都能存进长期记忆。

**第四个，错误容错**。比如记忆提取失败，我就静默跳过，不影响主流程；比如 JSON 解析失败，我有三层兜底。

## 【第五部分：我的收获和下一步计划】（1.5分钟）

老师，做完这个项目我有几个收获：

**第一**，我理解了 AI Agent 的核心原理——就是大模型 + 记忆 + 工具 + 自主循环。不是简单调个 API，而是要设计一套让它自己干活的机制。

**第二**，我对软件工程有了更深的体会——分层、设计模式、错误处理、安全意识，这些不是课本上的概念，是真做项目才知道有多重要。

**第三**，我知道自己项目的局限在哪里：记忆检索还是关键词匹配，比较粗糙；现在是单 Agent 调工具，还没有多 Agent 协作；也没有接 RAG 检索增强。

如果以后跟着您做项目，我计划往这几个方向深化：一是把记忆检索升级成向量检索；二是做多 Agent 协作；三是接咱们学校的论文库做 RAG。
